1. 项目定位与使用场景

本项目把船舶分段生产台账转换为交互式横道图（甘特图）。横轴表示日期，纵轴表示船舶或分段，横条表示某个生产阶段的开始与结束。使用者可以先查看船队生产跨度，再点击一艘船观察分段的阶段分布、工期和未填写的节点。

它由可独立打开的图表页面、本地 HTTP 服务、Windows 窗口控制台、Excel 处理程序和在线表同步脚本组成。没有数据库服务，也没有 React、Vue 等前端框架。图表数据保存为 data.js 快照，浏览器直接加载。

典型用途包括：核对分段上胎与下胎时间；比较船舶生产周期；查找尚未补全工期的分段；按船号或分段号筛选；把当前视图导出成 Excel；通过 WPS AirScript 定时更新本地数据。

本工具主要用于查看、汇总和交换生产数据，不是带资源约束的自动排产系统。当前没有任务依赖线、关键路径计算、多人协同编辑或向源 Excel 回写排期的机制。

2. 功能说明

2.1 船队总览和单船钻取

默认每行是一艘船，汇总条使用当前阶段各分段的最早开始和最晚结束。总览的时间轴会延伸到最晚日期之后第三个月的月末，再增加边缘留白，便于观察后续空档。

点击船舶行进入单船分段视图；原来处于月视图时，进入后默认切换到日视图。每个分段对应一行，按当前阶段的起始时间排序，同一天再按分段号排序。左侧展示分段/船、类型、吨位、车间、开始日期和工期。点击“← 全部船”返回。

阶段切换由 PHASES 和 barOf() 控制。当前 setPhase() 主要更新阶段汇总缓存及可见行，不会主动重建排序和时间轴；搜索、钻取等后续重建操作会重新计算。这是现有实现的边界，不应把阶段切换理解为每次都完整重新排版。

2.3 时间轴、搜索和提示

月视图尽可能把完整周期铺入可视区域；周视图约为适配密度的三倍，并设置上下限；日视图在总览中放大，在单船中根据该船周期自适应。日视图或手动连续缩放达到足够密度时，网页显示日期数字行。

在横道图区域内按住 Ctrl 并滚动鼠标滚轮，可以连续调整时间轴：向上滚放大，向下滚缩小。缩放以红线选中的日期为锚点，尽量保持红线原有屏幕横坐标，让所选日期附近的时间间隔逐渐展开或收拢。该操作只调整时间轴，不放大整个页面的文字、左侧固定列或按钮；普通滚轮继续用于滚动页面。

当每天宽度达到 9 像素时，自动出现日号与逐日网格；达到 44 像素时，日号后增加星期。单船视图中的分段条随之展开，悬停仍可查看所有阶段的完整日期。总览不会因为放大而自动变成单船视图，需要分段明细时点击船舶行进入。

状态栏显示相对月视图的缩放百分比。手动缩放的下限是适配完整时间范围的月视图，上限为每天 64 像素。月/周/日按钮可随时退出手动缩放，恢复对应预设。手动密度在当前页面的窗口尺寸变化、阶段切换和视图重排后保留，若新范围要求更大的最小密度则调整到新下限；页面刷新后不保留。

如果红线日期仍在时间轴范围内、只是被横向滚出屏幕，下一次缩放会将该日期带回可视区域中间。如果红线日期已经不在当前视图日期范围内，则以当前可视时间区域中点缩放。接近时间轴首尾、或缩小到完整总览时，滚动位置会受到内容边界限制，红线无法始终保持原横坐标。

输入船号或分段号后，页面经过 220 毫秒防抖再筛选。匹配采用不区分大小写的包含搜索。搜索路径遍历全部分段，即使从单船界面开始输入，也不是仅限当前船。悬停分段时显示该分段各阶段的日期与工期信息。

时间轴背景用重复 CSS 渐变表示工作日和周末。图表支持横向、纵向滚动，左侧信息列和上方表头保持固定。

2.4 可拖动红色日期参考线（本次新增）

用鼠标按住红色虚线或顶部标签并左右拖动即可调整参考日期。线条拥有 18 像素宽的透明命中区域，实际可见虚线仍保持细线样式，减少“必须点得很准”的问题。

拖动按整天吸附。离开默认日期后，标签显示完整的 YYYY-MM-DD；上方状态栏同时显示参考日期。垂直滚动时标签跟随可视区域顶部，水平滚动时不会覆盖左侧冻结列。拖到时间区域左右边缘时会自动横向滚动。

点击“定位今天”或双击红线恢复默认日期。红线获得键盘焦点后，方向键移动一天，Shift 加方向键移动七天，Home/End 移到当前时间轴首尾。界面采用 Pointer Events，鼠标、触控笔和触摸指针共用同一套处理逻辑。

参考日期保留在当前页面内存中，缩放、窗口大小变化和视图操作不会主动重置它；刷新页面或控制台重新加载图表后恢复默认。若所选日期不在新视图时间范围内，或筛选结果没有行，红线隐藏；状态栏仍保留选中的参考日期。

数据口径：页面原有 today 来自 data.js 的生成日期，不是浏览器每次打开时的系统日期。本次新增独立的 markerDay，拖动不改变 today，不重算生产工期，不修改源 Excel、不写回 data.js。导出的 Excel 仍使用原有快照“今天”列，临时拖动位置不写入导出文件。例如旧数据生成于 10 月 22 日，11 月打开旧快照时“定位今天”仍回到 10 月 22 日；重新生成数据才更新该基准。

2.5 取数与生成图表

支持以下路径：

  1. 本地 Excel：用 build.py 或控制台选择 .xlsx/.xlsm 文件和工作表，读取固定列结构，生成 data.js。
  2. WPS 直连：配置 AirScript webhook 与令牌，通过 gantt_sync.py 分页读取在线表，转换为规范字段，再生成数据。
  3. 在线表链接：直接文件链接下载到 DATE 后读取；普通 kdocs/WPS 分享链接则使用已配置的 AirScript webhook 读取整表、保存为 Excel，再从该 Excel 生成图表。分享链接本身不提供自动登录能力，也不保证与当前 webhook 指向同一文件，需要使用者核对配置。
  4. 通用 URL 拉取：pull.py 接收 JSON 或 CSV，支持单次执行及间隔循环。
  5. Webhook 推送：外部程序把 JSON 或 CSV POST 到本地服务，由服务归档并生成新快照。

控制台还提供列出工作表、预览前几行和实际调用接口检查令牌的功能。查看器自身不轮询 data.js；控制台内的取数任务成功后会重载 iframe，独立页面或由外部计划任务更新后的页面需要刷新才读取新快照。

2.6 Excel 导出

“导出 Excel”把当前阶段、筛选行及当前时间轴完整范围传给本地服务。导出的是当前视图的全部行，不只是屏幕上虚拟化渲染的少量 DOM 行，也不是网页截图。

导出内容包括标题、月份、左侧六列、按天铺设的彩色条、快照今天列、图例以及冻结窗格。网页缩放参数参与表头选择，但 Excel 每天列宽固定为 3.0，不是逐像素复刻网页。后端同时把文件保存到 DATE，并返回二进制下载。

直接以 file:// 打开查看器可以看图、筛选和拖动红线，但不能调用本地 /api/export；导出需要窗口/HTTP 服务运行。

2.7 定时任务、日志与设置

Windows 计划任务名为 Gantt_Sync。界面支持安装或重建、暂停、恢复、立即运行和删除，展示上次/下次执行时间与结果。周期默认 120 分钟，安装逻辑限制最短 5 分钟。源码模式执行 Python 同步脚本，EXE 模式执行当前程序的 --gantt-sync 参数。

日志页面分别读取同步日志 gantt.log、服务日志 service.log 和窗口日志 logs/window.log。设置页面维护 webhook、工作表和 AirScript 令牌；令牌可写入同步配置，同时可选写入用户环境变量。

3. 总体架构与数据流

本地 Excel ───────────────→ build.py ──────────────┐
                                                   │
在线表 → AirScript → gantt_sync.py → core.py ──────┤
                                                   ├→ data.js → viewer.html
通用 URL → pull.py ────────────────→ core.py ──────┤               ↑
                                                   │               │ iframe
JSON/CSV 推送 → server.py ─────────→ core.py ──────┘             app.html
                                                                   ↕ HTTP API
在线链接 → panel.py → DATE/*.xlsx → build.py                  panel.py
                                                                   ↑
                                                window.py → 本地服务 + Windows 窗口

这不是“所有输入都调用同一个转换函数”的架构。build.py 自己实现 Excel 到 payload 的逻辑；core.py 实现字典记录到 payload 的逻辑，两者产出相同结构，但日期解析、完成状态判定和过滤条件存在差异。修改业务规则时需要同时核对两条路径。

图表采用快照式模型：后端批量生成数据，前端一次性加载到内存，再在内存中分组、筛选、计算跨度并绘制。没有数据库查询、WebSocket 推送或服务端分页显示。

4. 数据模型与字段映射

4.1 日期与字典压缩

日期统一转为相对 2020-01-01 的整数天数。Python 执行日期相减，JavaScript 通过 UTC 转换和固定偏移 18262 天衔接 Unix 时间，避免浏览器本地时区影响显示日期。

缺失日期使用 0；因此本实现不能无歧义表示恰好为纪元日的真实生产日期。项目面向后续年度生产台账，维护者仍应知道这一哨兵值约定。

重复字符串用字典表压缩：types、areas、shops 保存实际文本，分段只存索引；-1 表示没有对应字典项。hulls 保存船舶汇总信息。这样可以减少数千行数据的重复文本和文件体积。

5. 业务计算原理

5.1 日期解析与数据清洗

build.as_day() 只接受 Python 的 datetime/date，所以源 Excel 应存储真正的日期单元格。load_workbook(read_only=True, data_only=True) 按只读方式读取公式缓存值；程序不会计算 Excel 公式。纯文本日期或未被 Excel/WPS 计算保存的公式可能无法提供预期日期。

core.parse_day() 更宽松：支持日期对象、合理区间内的 Excel 序列号、年月日字符串、斜杠/点分隔日期和部分紧凑格式。非法值、布尔值与缺失标记返回 0。在线链接先落地 Excel 的路径通过 _to_date() 转换日期列，尽量恢复为日期单元格。

缺船号的行被跳过。core.py 检查九个原始节点是否至少一个有效；build.py 当前过滤条件没有包含“只有舾装完工”或“只有转序日期”两种情况，因此同一份稀疏数据走不同路径可能得到不同数量。吨位统一尝试转为浮点数并保留一位小数，转换失败为 0。

5.2 完成状态与借用转序日期

Excel 路径把船体状态中包含“完成”的行加入完成集合；通用核心路径还识别“完工”“已完工”“已交”“已转”等关键词。按船分组后，以“上胎日期，否则结构成品化日期，否则很大的排序值”和分段号排序，再反向扫描。

若某个被标记完成的分段缺少转序日期，则尝试借用排序中后续可用的转序日期；找不到后续值时尝试该船已有的最晚转序日期，并要求不早于上胎日期。若整艘船完全没有转序日期，就没有可借用的值，程序不会凭空补出日期。

借用日期属于显示计算的推断值，当前 payload 没有另存“原始/推断”标志，因此后续查看者无法仅从 data.js 区分。原 Excel 不会被回写。

5.3 阶段条与未完工处理

对于普通阶段，barOf() 的规则为：起止均缺失则没有条形；只有终点则起点取终点；只有起点且分段已完成时用转序日期兜底，否则未完工且起点不晚于快照今天时延伸到快照今天；起点在未来则先画一天；起止颠倒时交换。工期按 结束 − 开始 + 1 计算，是含首尾两天的自然日，不扣除周末或节假日。

当前前端 isDone() 的判断是“结构成品化或转序日期任意一个存在”，并非只看最终转序日期。因此成品化字段已填而转序字段未填的分段，也不会按普通在建分段一直延伸到今天。

船舶汇总调用严格模式 barOf(..., true)，不把缺终点的分段无条件延长到今天。全流程使用所有阶段有效日期的最早/最晚值，只有完全缺少有效终点时才执行其未完工延伸规则，不代表每个未结束子阶段都被单独延伸。

未完工条右侧使用斜纹提示，工期带星号；无日期的当前阶段显示“— / 待定”。一条分段若所有日期都被生成器过滤掉，就不会进入前端，也不会作为“待定”行出现。

6. 前端实现详解

6.1 viewer.html 的组成

样式、页面结构与行为脚本集中在一个文件中。初始化读取 window.GANTT，计算日期范围、构建按船分组的 byHull，生成船舶顺序，并建立阶段跨度缓存 spanCache 和分段排序缓存 sortedCache。

主要状态包括 phaseKey（阶段）、focus（船舶索引，-1 为总览）、scaleKey（密度预设）、rows（逻辑行）、px（每天像素数）、viewStart（时间轴起日）、totalDays（总天数）、markerDay（参考日期）及 customPx（手动密度，null 表示使用预设）。

rebuildRows() 按搜索、单船、总览三种分支生成逻辑行。computeRange() 决定显示日期区间；layout() 设置尺寸、背景、表头与参考线；bindRow() 将某条逻辑记录绑定到复用的 DOM 节点。

6.2 行虚拟化

每行高度固定为 34 像素。renderWindow() 根据 scrollTop 和视口高度计算当前可见行，再添加上下各约六行的缓冲，只创建需要的节点数量。节点放进 pool，滚动时更新文本、条形和 translateY()，不为每个分段都创建一套 DOM。

因此，几千条数据仍全部保留在内存，但实际参与页面布局的行大致为“可见行数 + 缓冲”。这降低的是 DOM 渲染成本，不是后端取数总量。滚动监听通过 requestAnimationFrame 合并更新，避免每次滚动事件都立即重画。

6.3 坐标换算

某天对应的内容坐标：

参考线 x = LEFT_W + (markerDay - viewStart + 0.5) × px
阶段条 x = (开始日期 - viewStart) × px
阶段条宽度 ≈ (结束日期 - 开始日期 + 1) × px

其中 LEFT_W = 460，参考线加半天宽度以落在当天列中心。拖动反算要同时考虑视口左边界、横向滚动量、固定信息列宽度和按下位置相对线心的偏移量。

日期 = viewStart + round((鼠标局部 x + scrollLeft - LEFT_W - 按下偏移) / px - 0.5)

最后限制在当前时间轴首日至末日之间。这样放大、缩小或横向滚动后，鼠标位置依然能映射到正确的日期，而不是把像素偏移直接当作天数。

6.4 拖动生命周期

pointerdown 保存指针 ID、按下偏移和横坐标，并使用 setPointerCapture() 捕获后续事件；pointermove 更新参考日期；动画帧循环检查是否接近左右边缘，在需要时每帧滚动 12 像素。pointerup、pointercancel、捕获丢失或窗口失焦都会清理拖动状态和动画帧，避免松手后继续移动。

updateMarker() 只更新参考线位置、日期标签、可访问性属性与状态栏，不重建分段数据。标签限制在可视时间区域内；当红线横向滚到固定列后面时隐藏，避免遮挡船号。红线阻止点击冒泡，从而不会因释放鼠标误触船舶钻取。

通过 role="slider"、tabindex 和 aria-valuetext 提供键盘与辅助技术语义。touch-action:none 限制在拖动把手上，避免拖线时触发页面的默认触摸平移。

6.5 Ctrl＋滚轮连续缩放实现

查看器在滚动容器 vp 上以 { passive: false } 注册 wheel 监听。只有按下 Ctrl 才调用 preventDefault() 拦截浏览器整页缩放，普通滚轮事件保持默认行为。根据 deltaMode 将像素、行和页三种滚轮单位统一换算，再通过指数倍率 新密度 = 当前密度 × exp(-滚动量 × 0.002) 连续改变时间间距。

同一绘制帧内的滚轮变化累积到 wheelZoom，由 requestAnimationFrame 统一应用，减少重复布局。每次变化先记录红线日期对应的屏幕横坐标，然后设置 customPx 并调用 layout(true)：这里的 true 表示保留既有日期范围，只重算像素宽度、表头、背景和可见行。最后反算滚动位置：

新 scrollLeft = LEFT_W + (锚点日期 - viewStart) × 新 px - 锚点屏幕 x
锚点日期 = markerDay + 0.5（红线位于当天中心）

这使连续缩放围绕红线发生，而不是围绕鼠标位置或总时间轴起点发生。日期超出范围时回退到可视中点；浏览器会把滚动值限制在可用区间。缩放前终止尚未结束的红线拖动，避免旧按下偏移量与新密度混用。预设按钮会清空待处理的滚轮变化与自定义密度。

showDayHeader() 根据当前密度决定日级表头与网格；导出 payload 在手动模式下据此选择 day 或 month 表头，后端仍按固定 Excel 单元格列宽输出。生产日期、工期、筛选数据和 window.GANTT 不参与修改。

6.6 app.html 控制台

控制台用侧边导航组织图表、取数、计划任务、日志和设置。图表嵌在 viewer.html?embed=1 的 iframe 中；该参数隐藏重复的品牌标题。所有后台操作通过封装的 fetch() 调用 HTTP API，并带 X-Panel: 1。

启动取数任务后，前端以任务 ID 轮询进度，约每 400 毫秒读取新增日志；任务完成后显示结果，成功的数据更新会重载 iframe。总体状态每 20 秒刷新，但这一状态轮询本身不等价于持续重载图表数据。

7.1 任务管理和并发

panel.start_job() 为任务创建 ID、状态、起止时间、日志和结果，再启动守护线程。_run_job() 在运行锁内执行具体函数，并临时包装标准输出，将进度送入日志缓冲。状态最终为完成或错误，前端用 since 游标获取增量日志。

HTTP 服务器可并发处理请求。Webhook 生成过程有单独的锁，控制台任务也有自己的锁；两者并不是统一覆盖所有入口的全局写入事务。core.write_js() 原子替换可防止读到半份文件，但不会解决所有跨进程“最后一次写入覆盖前一次”的业务竞争。build.py 当前直接写目标文件，不具备同样的原子写入保障。

7.2 网络恢复

net.request() 优先尝试不使用代理的 urllib opener，然后尝试系统/环境代理，最后调用 curl.exe。这用来应对本机曾使用代理软件、代理退出后系统仍残留无效地址的情况。

网络连接失败会按重试次数再次尝试；HTTP 4xx/5xx 不会在底层当作普通代理错误吞掉。gantt_sync.call() 对 401/403 转换成易读的令牌错误，并处理 WPS data.result 可能被重复 JSON 编码的情况。

7.3 桌面窗口和资源定位

window.py 先探测目标端口上是否已有本项目服务，有则复用。否则从目标端口起寻找可用端口并启动服务。正常情况下由 pywebview 打开约 1560×960 的独立窗口，通过本地 URL 加载控制台；没有可用 pywebview 时尝试 Edge 应用模式。

源码运行时 BASE 为源文件目录；PyInstaller 打包后 BASE 为 EXE 所在目录，RES 为解包资源目录。静态文件服务先检查 BASE，找不到才查打包资源，因此可以在 EXE 同级放新版 viewer.html 覆盖内置查看器，无需更改生产数据或重新打包。

paths.load_env() 只补充进程中缺失的 Windows 用户/系统环境变量；已有值不覆盖。ensure_defaults() 仅在 EXE 同级缺少配置/数据文件时复制默认资源，不应当作“每次恢复默认配置”。

8. 在线表脚本和接口

8.1 AirScript 分页协议

airscript_sync_task.js 运行在 WPS 环境中。请求形状为：

{"Context":{"argv":{"action":"data","sheet":"Sheet1","row_start":1,"row_count":500}}}

action=meta 返回工作表名称、最后行号和最后列号；action=data 返回二维单元格数组与下一行号。脚本依据 UsedRange 的起始行列和范围大小计算绝对末行末列，避免前面有空行时表头错位。

脚本使用 Application 和 Context，顶层返回 JSON 字符串，供 WPS 放入 data.result。它不是普通 Node.js 脚本，不能把顶层 return 文件直接当作标准 Node 应用运行。客户端默认每次 500 行，实际由 rows_per_call 控制；循环按收到的行数推进。

8.2 推送脚本

wps_gantt.js 是另一条接入路径：从配置的来源 URL 读取记录，或从活动工作表连续区域读取第一行表头，再用 fetch() 推送到本地 /webhook/gantt。它不是分页同步脚本的替代品。

推送脚本要求所在运行环境具备网络能力并能访问目标服务器。云端 AirScript 中的 127.0.0.1 不指向用户电脑；无法到达本地服务时应使用本机主动拉取路径或实际可达的服务地址。

13. 已知限制及可扩展方向

  1. “今天”采用快照生成日期，页面跨日不自动推进。若要改为实时系统日期，应重新评估未完工延伸、汇总、导出和历史快照的一致性。
